# 额度有据 · 交互原型

这是一个**离线、无依赖**的交互原型，用来评审「一次生成 = 一次可解释的额度事务」的产品方案与界面状态。

它不是真实应用，不修改 `src/`，不连接 Wasp、PostgreSQL 或模型服务。

## 打开

双击 `prototype/index.html`，或直接拖进浏览器即可。

- 无需安装、无需启动服务。
- 不引用 CDN、远程字体或任何外部资源。
- 建议使用 Chromium 系浏览器；截图为 Chrome 151，视口 1440 × 1100。
- 原型用 650ms 模拟延迟便于观察生成中状态；真实 `mockAi.ts` 约 500ms，不影响断言。

## 界面

- **左侧产品视图**：模拟任务规划页。显示余额、生成成本、最后 1 个额度提示、零额度提示、生成回执与日程。
- **右侧验收台**：模拟服务端事务与验收环境。包含场景按钮、不变量、对账公式、请求轨道、事件日志与验收结果表。

页面中所有数字与日志均为模拟数据，不能作为真实后端、数据库或并发安全的证据。

## 可执行场景

每个场景都会重置为固定前置条件，并自动跑完；连续点击场景会重新开始。

| 场景 | 前置 | 操作 | 预期 |
| --- | --- | --- | --- |
| **P1 成功扣 1** | 余额 3，正常任务 | 生成一次 | 余额 2；1 次预占、1 次模型调用、1 次成功；出现成功回执和日程 |
| **P2 零额度拦截** | 余额 0 | 按钮禁用；再模拟一次绕过页面的直连请求 | 按钮不可点；页面警告可见；服务端拒绝，模型调用为 0，余额 0 |
| **P3 失败自动返还** | 余额 2，第二个任务带 `[fail]` | 生成一次 | 模型失败；余额从 2 预占至 1，再返还至 2；净扣 0；出现失败回执与重试 |
| **P4 并发只放行 1 个** | 余额 1 | 两个请求在同一 tick 发起 | 只有一个预占成功；1 次模型调用、1 次成功、1 次拒绝；余额 0；轨道出现两条路径 |

「运行全部场景」按 P1 → P4 顺序执行，并在验收结果表中保留四行 PASS/FAIL 对照。

实际走查结果、操作步骤与截图见 [ACCEPTANCE.md](../ACCEPTANCE.md)。

其他可操作项：

- **向第二个任务注入 `[fail]`**：控制下一次手动生成是否触发模拟失败。
- **重置演示**：恢复余额 3、清空结果与日志。
- 场景运行结束后，如果余额仍大于 0，可以手动点击「生成日程」，观察回执、余额与旧日程标注。
- 失败回执里的「重试本次生成」会保留当前注入设置，重新发起一次请求。

## 日志与口径

事件名与 [SPEC.md](../SPEC.md) 的服务端日志设计一致。原型覆盖的每个结局都以 `quota.attempt.started` 开始、以 `quota.settled` 结束；成功路径包含模型调用与保存，失败路径包含返还，被拒绝的路径不出现 `mock-ai.started`（未知异常 500 不在此原型中，按 SPEC 不写 `quota.settled`）：

`quota.attempt.started` → `quota.reserved` / `quota.rejected` → `mock-ai.started` → `mock-ai.succeeded` / `mock-ai.failed` → `quota.refunded`（失败时）→ `plan.saved`（成功时）→ `quota.settled`

对账公式：

```text
初始额度 − 预占次数 + 返还次数 = 当前余额
```

- 被拒绝的请求没有预占，也没有模型调用。
- 模型失败会返还预占的 1 个额度，所以一次失败请求净变动为 0。
- 成功请求不返还预占，所以净变动为 −1。

## 原型能证明什么、不能证明什么

**能演示：**

- 预检、预占、核销、返还的状态机与用户可见反馈是否连贯。
- 成功、零额度、模型失败、并发落败时，余额、回执、日志与验收口径是否自洽。
- 同一账号余额 1、两个请求时，产品希望服务端保证的结果。

**不能证明：**

- 真实并发安全。页面内是单线程 JS 模拟器，不是两个并行事务。
- Wasp action 的查询失效、Prisma 条件更新、数据库隔离级别、登录与权限行为。
- 真实网络超时、进程崩溃、重复请求或跨标签页自动同步。

真实后端与并发验证必须在实现阶段用 Wasp、PostgreSQL 与真实双请求执行，见 [TASKS.md](../TASKS.md) 的 T6 和 [ACCEPTANCE.md](../ACCEPTANCE.md) 的 AC-04、AC-05。

## 无障碍与降级

- 生成状态区使用 `role="status"` + `aria-live="polite"`，不依赖 toast。
- 所有按钮、输入框、任务复选框均可用键盘操作，有可见 `focus-visible` 样式。
- 颜色之外还有文字、图标与节点标签表达状态。
- 支持 `prefers-reduced-motion`。
- 窄屏下双栏堆叠，原型不横向溢出。
