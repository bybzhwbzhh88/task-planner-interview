# 04 验收案例：日程生成的额度处理

## 判断、方案与状态

- **判断**：验收的关键不是“功能能跑”，而是四条边界能否被观察到——不足时不调用、失败时不扣、并发不透支、每种结果用户都能区分。
- **方案**：用 AC1–AC4 覆盖 TASK 要求的四类场景，AC5 作为文案与状态一致性检查；每条案例写清前置条件、操作、可观察结果和证据来源。
- **状态**：[案例已定义；AC1–AC3 可由产品侧走查或技术侧运行验证，AC4 需技术方向提供可重复脚本；实际结果待技术方向回写]。

> 规则见 01 第二节；流程与页面状态见 02；任务对应见 03。本文只定义“怎么验、看什么”。

## 二、案例明细

### AC1 成功生成消耗 1 额度

| 项 | 内容 |
|---|---|
| **前置条件** | 账号已登录；剩余额度 = 3；待办任务至少 1 条；模型模拟接口正常返回成功 |
| **操作** | 点击“生成日程”，等待请求完成 |
| **可观察的预期结果** | ① 页面展示日程结果；② 剩余额度变为 2；③ 提示“生成成功，已消耗 1 额度”；④ 生成中按钮曾禁用；⑤ 模型调用日志出现 1 次已发起的调用 |
| **不应出现** | 额度一次减 2 或更多；结果出现但额度未减；额度先减后失败 |
| **证据来源** | 页面截图（结果 + 剩余额度）；模型调用日志；数据库 `User.credits` 查询 |
| **对应规则** | R1 |

---

### AC2 额度不足不发起模型调用

| 项 | 内容 |
|---|---|
| **前置条件** | 账号已登录；剩余额度 = 0；待办任务至少 1 条 |
| **操作** | 点击“生成日程”（或尝试点击） |
| **可观察的预期结果** | ① 页面提示“额度已用完，本次未发起生成”；② 剩余额度仍为 0；③ **不出现“生成中”状态**；④ **模型调用日志中没有新增已发起的调用**；⑤ 提供下一步入口（查看规则/联系管理员） |
| **不应出现** | 出现生成中；产生模型调用日志；额度变为负数；只弹开发者式 402 文案 |
| **证据来源** | 页面截图；模型调用日志（前后对比）；数据库 User.credits 查询 |
| **对应规则** | R2 |

> 关键证据是**调用日志无新增**，不能只凭页面提示判断。

---

### AC3 模型失败不消耗额度

| 项 | 内容 |
|---|---|
| **前置条件** | 账号已登录；剩余额度 = 1；构造模型明确失败的条件（按项目现有模拟失败方式） |
| **操作** | 点击“生成日程”，等待请求完成 |
| **可观察的预期结果** | ① 页面提示“生成失败，本次未扣额度”；② 剩余额度仍为 1；③ 不展示成功日程结果；④ 提供重试或修改任务入口 |
| **不应出现** | 额度变为 0；先扣后返还；把失败展示为成功；失败后无法重试 |
| **证据来源** | 页面截图；模型调用日志；数据库 `User.credits` 查询 |
| **对应规则** | R3 |

**补充案例 AC3b（重试只扣一次）**：额度 = 1，首次失败，重试成功 → 最终额度 = 0，成功结果 1 条，累计成功扣减仅 1 次。

---

### AC4 并发请求不透支

| 项 | 内容 |
|---|---|
| **前置条件** | 账号已登录；剩余额度 = 1；准备可同时发起两个生成请求的方式（脚本或多标签页） |
| **操作** | 同一账号**同时**发起 2 个生成请求 |
| **可观察的预期结果** | ① 成功生成次数 ≤ 1；② 最终剩余额度 ≥ 0（不为负）；③ 未成功的请求有明确提示“本次未扣额度，请稍后重试”；④ 不出现“扣了额度却没有结果”或“两个都成功” |
| **不应出现** | 额度变为 -1；两个请求都成功扣减；一个成功但额度扣了 2 次；被拒请求无任何提示 |
| **证据来源** | 并发脚本输出（成功次数、最终额度）；两次请求的返回；数据库 User.credits 查询 |
| **对应规则** | R4 |
| **可重复性要求** | 必须提供脚本或命令，说明运行方式，可重复执行并输出上述结果 |

> 本案例只约束用户可观察结果；实现方式（事务、条件更新等）由技术方向在 SPEC.md 说明。

---

### AC5 四类结果文案与状态可区分

| 项 | 内容 |
|---|---|
| **前置条件** | 能分别触发成功、额度不足、模型失败、并发被拒四种结果 |
| **操作** | 依次走查四种状态 |
| **可观察的预期结果** | ① 四种提示文案互不相同；② 每种状态的主按钮行为正确（可用/禁用/可重试）；③ 每种异常状态都有下一步入口；④ 剩余额度显示与实际一致 |
| **不应出现** | 四种情况共用“操作失败”；额度不足仍显示可点击生成；异常状态无出口 |
| **证据来源** | 四种状态截图对照；与 01 第五节文案表逐条比对 |
| **对应规则** | R5 |
