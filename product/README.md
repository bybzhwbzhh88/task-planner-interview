## 原型怎么用

直接双击 `prototype/index.html`，不需要安装依赖或启动服务。

右侧“演示场景”：

| 按钮 | 会发生什么 |
| --- | --- |
| 场景 1：成功生成 | 3 额度 → 2，展示日程，日志 `started` + `succeeded` |
| 场景 2：额度不足 | 余额 0，提示未生成/未扣，日志没有 `started` |
| 场景 3：模型失败 | 余额仍 3，失败提示，日志 `started` + `failed` + 退款 |
| 场景 4：并发 1 额度 | 3 个请求：1 成功、2 额度不足，最终 0，1 次模型调用 |
| 场景 5：并发 3 额度 | 5 个请求：3 成功、2 额度不足，最终 0，3 次模型调用 |
| 重置演示 | 恢复 3 额度、默认任务、空日志 |

原型是**前端模拟**：用同步 `reserve()` 模拟数据库的原子条件更新，不连接真实后端。它用于评审规则、文案和交互，不替代工程的真实并发测试。

## 运行原型逻辑测试

```sh
node product/prototype/quota-model.test.mjs
```

覆盖：

- 1 额度 / 3 请求：1 成功、2 不足、最终 0、模型只调用 1 次；
- 3 额度 / 5 请求：3 成功、2 不足、最终 0、模型调用 3 次；
- 模型失败：退款，余额恢复；
- 0 额度：直接拒绝，模型 0 调用；
- 连续生成直到耗尽：第 4 次拒绝。

## 与仓库现有代码的关系

当前仓库的额度逻辑在 [operations.ts](../src/demo-ai-app/operations.ts)；产品方案不直接改后端代码，但 PRD/TASKS 已写清工程落地要求：

- 模型调用前条件预扣，额度不足不调用；
- 模型/保存失败退款；
- 并发不透支；
- 成功/失败/不足都有明确文案和下一步。

产品方向的验收重点是**规则是否自洽、用户是否看得懂、交接是否可执行**，不是在本方向内完成 Wasp 后端实现。
