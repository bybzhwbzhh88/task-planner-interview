# 01 需求与方案：改进日程生成的额度处理

## 判断、方案与状态

- **判断**：当前额度逻辑是“有额度就扣 1、为 0 返回 402”的初始版本，缺三件事：额度不足时仍可能先发起模型调用、模型失败与扣减的因果关系对用户不透明、并发下扣减没有防透支保障。
- **方案**：把额度处理收敛为一条明确规则——**只有“模型明确成功”才扣 1，其余情况一律不扣**；额度检查放在调用模型之前；扣减与结果落库在同一事务内完成；所有结果状态都给用户可理解的提示和下一步。
- **状态**：[已完成需求与方案、流程/原型、任务拆解、验收案例；未实现代码，代码验证由技术方向完成]。

---

## 一、现状

| 项 | 现状 |
|---|---|
| 额度字段 | `User.credits`，新账号默认 3 |
| 扣减时机 | 生成日程时，额度 > 0 则创建 `PlanResult` 并 `credits - 1` |
| 额度不足 | 抛出 `HttpError(402, "User is out of credits")` |
| 模型失败 | 本地模拟接口在扣减前抛错，当前不会扣额度 |
| 并发 | 未处理，存在同一账号并发下额度被透支的风险 |
| 用户感知 | 只有剩余数字；402 文案面向开发者；失败/不足时无明确下一步 |

**问题归纳**：
1. 额度不足时是否已发起模型调用，缺乏明确约束和可观察证据。
2. “失败不扣额度”是现有实现的结果，但不是被明确表达和保护的产品规则。
3. 并发下扣减缺少防透支保障。
4. 用户不知道“这次扣没扣、为什么失败、接下来能做什么”。

---

## 二、目标规则（逐条转译）

| 规则 | 系统行为 | 用户可感知 |
|---|---|---|
| R1 成功扣 1 | 模型明确成功 → 落库结果 + 额度 -1，同一事务 | 展示结果，剩余额度减 1 |
| R2 不足不调用模型 | 额度 ≤ 0 时在调用前拦截，不产生模型调用 | 提示额度不足，按钮不可用，**不出现生成中状态** |
| R3 失败不扣额度 | 模型明确失败 → 不扣减、不落库成功结果 | 提示失败，并明确“本次未扣额度” |
| R4 并发不透支 | 同一账号并发请求，额度不会被扣成负数，成功次数 ≤ 可用额度 | 至多一个成功；被拒请求有明确提示 |
| R5 结果可理解 | 每种结果都有状态、原因、下一步 | 成功/不足/失败/并发被拒，文案各不相同 |

**关键因果**：额度检查 → 调用模型 → 判定结果 → 仅成功时扣减。扣减不能早于结果判定。

---

## 三、范围与假设

**范围内**：单服务、单数据库；额度检查、扣减、失败处理、并发防透支、用户提示。

**范围外（本期不做）**：
- 支付、订阅、充值等额度获取方式
- 跨账号防刷、风控
- 精确 Token 计价
- 服务崩溃后的自动补偿/对账
- 跨请求结果复用
- 额度明细流水页（本期只展示剩余额度，[可选：预留字段说明]）

**假设**：
- [A1] 一次成功生成固定消耗 1 额度，与任务数量无关。
- [A2] “模型明确失败”指模拟接口返回失败；超时/异常按失败处理，不扣额度。
- [A3] 并发被拒的请求，产品上按“未成功、未扣额度”处理，提示用户重试。
- [A4] 本期无额度恢复机制，用完后需[联系管理员]，**不引导购买**。

---

## 四、关键产品决定

| 决定 | 内容 | 理由 |
|---|---|---|
| D1 检查前置 | 额度 ≤ 0 时直接拦截，不进入生成中 | 满足 R2，避免无效模型调用 |
| D2 扣减后置 | 只有模型明确成功才扣减 | 满足 R3，让“失败不扣”成为规则而非巧合 |
| D3 同事务 | 成功结果落库与扣减同事务 | 避免“扣了没结果”或“有结果没扣” |
| D4 防透支 | 扣减时带额度条件，扣减失败则本次按未成功处理 | 满足 R4 |
| D5 状态互斥 | 生成中禁用按钮，避免用户误以为可重复点击 | 降低并发概率，改善体验 |
| D6 文案分层 | 不足 / 失败 / 并发被拒 三种文案分开 | 满足 R5，用户知道下一步 |

> D4 的具体技术实现由技术方向在 SPEC 中说明；本文只约束“结果不能让额度为负”。

| 状态 | 触发条件 | 页面展示 | 主按钮 | 提示文案 | 下一步 |

| 空闲·充足 | 额度 > 0 | 剩余额度 N | 生成日程（可用） | — | 可生成 |

## 六、边界情况

- 额度刚好为 1：成功一次后变 0，页面应进入“额度不足”态。
- 额度为 0 时重复点击：始终不发起调用，不出现生成中。
- 模型失败后重试成功：只扣 1 次。
- 同一账号两个请求并发：最多 1 次成功，额度不为负。
- [待确认] 生成结果页刷新后，额度显示是否与数据库一致。
