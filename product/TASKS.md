## 4. 工程交接

### 4.1 接口契约

| 场景 | HTTP | 返回/错误 | 前端处理 |
| --- | --- | --- | --- |
| 成功 | 200 | `{ schedule, remainingCredits }` | 展示日程；更新余额；提示扣 1 |
| 额度不足 | 402 | 明确错误码/文案 | 不展示日程；提示未扣；给下一步 |
| 模型失败 | 502 | 明确错误码/文案 | 保留余额；提示未扣；可重试 |
| 参数/任务错误 | 400 | 校验信息 | 定位到任务或时长 |
| 未登录 | 401 | 登录提示 | 跳转登录 |

建议前端不要直接展示服务端原始异常文本；按状态码映射固定中文文案，避免泄露内部信息。

### 4.2 服务端

| 要求 | 具体做法 | 验收 |
| --- | --- | --- |
| 模型调用前预扣 | 先条件扣减，再调用模型 | 0 额度时无 `mock-ai.started` |
| 原子防透支 | `UPDATE ... WHERE id=? AND credits>0` 或等价条件更新 | 并发 1 额度只有 1 个成功，余额不为负 |
| 失败退款 | 模型失败/结果保存失败时 `credits+1` | 失败后余额恢复，结果不落库 |
| 成功落库 | 模型成功且 `PlanResult` 保存成功才确认扣费 | 成功 1 次 = 1 条结果 = 扣 1 |
| 校验顺序 | 登录 → 任务非空 → 时长 → 额度 → 模型 | 无任务/非法时长不扣费、不调用 |
| 日志 | `credit.reserved`、`credit.refunded`、`credit.insufficient`、`mock-ai.*` | 可按请求/`callId` 对账 |
| 退款失败 | 记录 `credit.refund_failed`，返回失败，人工修正 | 不静默吞错 |

数据模型可以不改：`User.credits` 足够表达余额。可选的防御性措施是加 `CHECK (credits >= 0)`，但它不能替代条件更新。

### 4.3 前端

- 顶部余额始终可见；成功后立即更新，失败/不足不变。
- 生成中禁用按钮，防止同一页面重复提交。
- 0 额度时禁用按钮并常驻提示；服务端 402 作为旧页面/并发兜底。
- 成功/失败/不足都用页面内持久横幅，不只靠 toast。
- 错误文案按状态映射，避免直接显示英文异常。
- 生成失败后给出可执行动作：删除 `[fail]` 任务、稍后重试、刷新确认余额。

### 4.4 测试

| 测试 | 方法 | 必须覆盖 |
| --- | --- | --- |
| 并发 1 额度 | 10 个并发请求 | 1 成功、9 个 402、余额 0、结果 1、`started` 1 |
| 并发 3 额度 | 10 个并发请求 | 3 成功、7 个 402、余额 0、结果 3、`started` 3 |
| 模型失败 | 含 `[fail]` 任务 | 502、余额不变、结果 0、`started` + `failed` 各 1 |
| 额度不足 | 余额 0 | 402、无 `started`、余额 0、结果 0 |
| 失败退款后重试 | 失败 → 删除 `[fail]` → 再生成 | 第一次不扣，第二次扣 1 |
| 连续耗尽 | 3 额度连续生成 4 次 | 前 3 次成功，第 4 次 402，余额 0 |

产品方向的原型逻辑测试命令：

```sh
node product/prototype/quota-model.test.mjs
```

工程实现后，建议用真实 Wasp 服务 + PostgreSQL 重跑 [ACCEPTANCE.md](ACCEPTANCE.md) 的 E-AC 案例，并把 HTTP 状态、`mock-ai.started` 计数、`User.credits`、`PlanResult` 数量记录到 SUBMISSION。

## 5. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 只做前端禁用，服务端没预扣 | 并发/旧页面仍可透支 | 服务端必须条件更新；前端只是体验层 |
| 预扣后进程崩溃 | 额度可能少 1，结果未生成 | 本题不要求崩溃补偿；记录日志，后续可加预扣流水/对账 |
| 退款失败 | 用户被误扣 | 记录 `credit.refund_failed`，人工修正；验收标注未覆盖 |
| 多标签页/网络重试 | 可能重复生成、重复扣费 | v1 不做幂等；产品文案提示不要连续点击，后续加幂等键 |
| 成功后刷新 | 最近日程不保留 | v1 已知限制；后续增加历史记录 |
| 额度不足无自助恢复 | 用户只能找管理员 | 本地练习项目无支付；文案明确“联系管理员” |
| 真实环境未跑 | 产品方案无法证明服务端并发 | 工程交接必须跑并发脚本，未跑要标注 |
