## 2. 研发接手时要确认的三个点

**处理资格的作用域。** 单执行进程可使用按`userId`的进程内协调；取得资格必须是原子动作，早于异步读余额和模型调用。如果实际有多个worker，改用数据库协调并补充验证，不能照搬进程内方案。

**条件扣额的失败分支。** 事务内仅允许`credits>0`的当前用户扣额；更新0行时回滚结果创建。模型调用不放在长数据库事务里等待。网络失联不等于事务回滚，业务结果仍以持久化状态为准。

**日志与现有字段的区别。** 当前日志仅有`event/callId`；D07的`requestId/userId/planResultId/outcome`是新增日志上下文，不代表现有数据库字段。新增日志能关联单次操作；不因此承诺跨请求去重或完整请求状态查询。

## 4. 完成与交接标准

研发交付改动、运行说明、接口契约和验证入口；测试按用例记录页面、HTTP、余额、结果数与调用日志。原始证据不覆盖，新结果按提交版本和运行时间另建目录。

所有核心规则及本轮补充用例通过后，才标记“实现验收完成”。若测试环境无法注入回滚或断网，明确记录阻塞条件和负责人，不以代码阅读代替实测。工时和上线时间待研发评估，本材料不作未经确认的排期承诺。
