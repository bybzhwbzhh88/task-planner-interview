# 额度处理验收案例

> 规则、状态与固定文案见 [PRD.md](PRD.md)，流程和边界见 [FLOW.md](FLOW.md)。本轮只交付产品方案，以下案例均未执行。

## 1. 测试准备

### 环境

- 使用本地项目和一个测试账号。
- 测试账号余额可通过数据库调整为 0、1、2、3。
- 任务列表中存在至少一条普通任务；模型失败场景额外准备一条包含 `[fail]` 的任务。
- 模型调用以服务端 `mock-ai.started` 日志计数；一次日志代表一次已发起调用。
- 每次案例开始前记录：账号余额、任务数、日程结果数、模型调用数。

### 记录格式

每个案例完成后记录：

```text
案例编号：
操作时间：
操作人或执行方式：
预期：
实际：
证据（截图/日志/查询结果）：
结论：通过 / 不通过 / 未执行
```

## 2. 核心验收

### AC-01 余额与成本可见

- **前置条件**：测试账号余额为 3；存在至少 1 条任务。
- **操作**：登录并打开任务规划页。
- **预期结果**：
  - 首屏显示“剩余额度 3 次”。
  - 按钮附近显示“每次成功生成消耗 1 个额度，失败不扣”。
  - 有任务时按钮可点击，文案包含“消耗 1 额度”。
- **证据**：页面截图。
- **当前状态**：未执行。

### AC-02 成功生成消耗 1 个额度

- **前置条件**：余额为 1；存在不含 `[fail]` 的任务；记录当前日程结果数。
- **操作**：点击“生成日程 · 消耗 1 额度”，等待完成。
- **预期结果**：
  - 页面出现本次日程。
  - 成功提示写明“已消耗 1 个额度，剩余 0 个”。
  - 页面余额刷新为 0。
  - 日程结果数增加 1。
  - `mock-ai.started` 增加 1 次。
  - 刷新页面后余额仍为 0。
- **证据**：成功提示截图、余额截图、结果数查询、模型调用日志。
- **当前状态**：未执行。

### AC-03 额度不足不调用模型

- **前置条件**：余额为 0；存在至少 1 条任务；记录 `mock-ai.started` 次数。
- **操作**：打开任务规划页，尝试生成日程。
- **预期结果**：
  - 生成按钮不可用，不出现“生成中…”等待，不发送生成请求。
  - 显示“额度不足”“本次未生成，也未扣除额度”“请联系管理员补充额度”。
  - 余额保持 0。
  - 日程结果数不变。
  - `mock-ai.started` 次数不变。
- **证据**：页面截图、余额查询、结果数查询、模型日志。
- **当前状态**：未执行。

### AC-04 模型失败不扣费且可重试

- **前置条件**：余额为 2；任务中包含 `[fail]`；记录结果数。
- **操作**：点击生成，等待失败。
- **预期结果**：
  - 显示“生成失败，额度未扣除”，并提示任务和时长已保留。
  - 页面余额仍为 2。
  - 日程结果数不变。
  - `mock-ai.started` 增加 1 次，`mock-ai.failed` 增加 1 次。
  - 提前预留的额度已释放，账实一致。
  - 任务和“今天可用的工作时长”未被清空。
  - 按钮恢复可点击。
- **补充操作**：删除 `[fail]` 任务后再次生成。
- **补充预期**：生成成功，余额从 2 变为 1。
- **证据**：失败提示截图、余额前后查询、日志。
- **当前状态**：未执行。

### AC-05 并发请求不透支

- **前置条件**：余额为 3；任务可成功生成；记录结果数。
- **操作**：使用同一账号，同时发起 10 个生成请求。必须并发发起，不能串行点击；可在两个以上标签页同时操作，或由开发用接口/脚本并发调用。
- **预期结果**：
  - 恰好 3 个请求成功，7 个请求因额度不足失败。
  - 成功请求各生成 1 条日程，共增加 3 条结果。
  - `mock-ai.started` 增加 3 次，不多于 3 次；预留失败的请求没有调用模型。
  - 最终余额为 0，不存在负数。
  - 失败页面或响应说明“额度已被用完，本次未扣费”。
- **证据**：并发请求结果汇总、余额查询、结果数查询、模型日志、预留与释放日志。
- **当前状态**：未执行。
- **备注**：只测快速连点不足以覆盖此案例，因为同一页面按钮可能天然只发一次请求。

### AC-06 同一页面重复点击

- **前置条件**：余额为 3；存在可成功生成的任务。
- **操作**：在生成按钮上快速连续点击 5 次。
- **预期结果**：
  - 第一次点击后按钮立即显示“生成中…”并禁用。
  - 只产生 1 次生成请求。
  - 成功后余额为 2，结果数增加 1。
- **证据**：录屏或请求数、余额与结果数查询。
- **当前状态**：未执行。

### AC-07 多标签页余额刷新

- **前置条件**：同一账号在两个标签页打开页面，余额为 2。
- **操作**：标签页 A 生成成功；切到标签页 B 再生成。
- **预期结果**：
  - 标签页 B 在操作后显示最新余额。
  - 两次都成功时最终余额为 0，不出现负数。
  - 第二次因余额不足失败时，提示未生成、未扣费，并刷新为 0。
- **证据**：两个标签页截图、余额查询。
- **当前状态**：未执行。

### AC-08 结果保存失败不扣费

- **前置条件**：余额为 1；模型可成功返回；通过测试手段让结果保存失败。
- **操作**：生成日程。
- **预期结果**：
  - 用户看到“生成结果未保存，额度未扣除”。
  - 余额恢复为 1。
  - 结果数不变。
  - 页面不展示伪成功日程；若保留旧日程，必须标注“不是本次结果”。
  - 用户可再次生成。
- **证据**：错误提示、余额前后查询、结果数查询。
- **当前状态**：未执行。
- **备注**：这是开发测试场景，不要求在产品界面提供触发入口。

### AC-09 输入边界不扣费

- **前置条件**：已登录；分别准备无任务、非法时长两类情况。
- **操作**：
  1. 无任务时查看生成按钮。
  2. 将工作时长设为小于 1 或大于 24，查看生成按钮。
- **预期结果**：
  - 无任务时显示“请先添加待办事项”，生成按钮不可用。
  - 非法时长时在输入处显示“工作时长范围 1–24 小时”，生成按钮不可用。
  - 两种情况都不进入生成中、不调用模型、余额不变。
- **证据**：页面截图、余额查询、模型日志。
- **当前状态**：未执行。

### AC-10 余额读取失败可恢复

- **前置条件**：已登录；存在至少 1 条任务；记录当前余额、日程结果数和 `mock-ai.started` 次数。
- **操作**：通过测试手段让余额查询失败，打开或刷新任务规划页；恢复后点击刷新入口。
- **预期结果**：
  - 页面显示“额度暂不可用，请刷新”，并只保留刷新入口。
  - 生成按钮不可用，不发起模型调用，`mock-ai.started` 次数不变。
  - 余额与日程结果数不变；不会把不可用误报为 0 额度。
  - 刷新恢复后显示服务端最新余额；余额大于 0 时进入可生成状态，余额为 0 时按 AC-03 处理。
- **证据**：异常截图、恢复后截图、余额前后查询、模型日志。
- **当前状态**：未执行。

### AC-11 会话失效可恢复

- **前置条件**：已登录且能访问任务规划页；记录余额、模型调用数。
- **操作**：使当前会话失效，再打开任务规划页或触发需要登录的读取。
- **预期结果**：
  - 跳转登录页，并显示“登录已失效，请重新登录”；首次进入不显示该提示。
  - 不调用模型、不扣额度。
  - 重新登录成功后回到任务规划页，并读取服务端最新余额。
  - 不新增独立权限申请或浏览器权限弹窗。
- **证据**：登录页截图、登录前后余额、模型日志。
- **当前状态**：未执行。

### AC-12 超时或断网显示结果待确认

- **前置条件**：余额为 2；存在可成功生成的任务；记录结果数与模型调用数。
- **操作**：发起生成后，通过测试手段让客户端超时或断开响应；等待页面进入异常状态，再点击刷新。
- **预期结果**：
  - 显示“结果待确认”“不自动重试，请刷新后查看余额和日程；如余额减少但无日程，联系管理员核对”。
  - 生成按钮不可用，只保留刷新入口。
  - 不自动重发请求；模型调用数不得因页面停留或刷新而增加。
  - 刷新后以服务端余额和日程记录为准：
    - 余额减少且有新日程：确认本次已成功，按实际余额展示。
    - 余额未变且无新日程：本次未成功，用户可手动再次生成。
    - 余额减少但无日程：提示联系管理员核对，不自行重试。
- **证据**：异常截图、刷新前后截图、余额与结果数查询、请求日志、模型日志。
- **当前状态**：未执行。
- **备注**：超时可能发生在服务端已完成之后，因此不能断言一定未扣费。

### AC-13 关键事件可查询

- **前置条件**：测试环境可查询事件记录；依次经历查看余额、点击生成、成功、模型失败、额度不足、确定结果后的自动余额刷新，以及结果待确认后的手动刷新。
- **操作**：查询对应账号的事件记录。
- **预期结果**：
  - 可查询 `quota_balance_viewed`、`generate_clicked`、`generate_succeeded`、`generate_blocked_no_credit`、`generate_failed`、`quota_refreshed`。
  - 字段与 PRD 第 10 节一致：余额、失败原因、耗时或刷新触发来源按事件提供。
  - 事件包含账号内部标识和额度数值，不包含任务正文。
- **证据**：事件查询结果、样例字段。
- **当前状态**：未执行。

### AC-14 生成中离开后重新进入

- **前置条件**：余额为 3；存在可成功生成的任务；记录结果数与 `mock-ai.started` 次数。
- **操作**：点击生成后，在请求完成前刷新、关闭或离开页面；等待请求可能已结束的时间，再重新进入任务规划页。
- **预期结果**：
  - 重新进入后显示服务端最新余额，并显示“上次生成结果未确认”。
  - 不自动重发请求；重新进入本身不得增加 `mock-ai.started` 次数。
  - 不自动展示或恢复上次日程；用户可点击刷新核对服务端记录。
  - 最新余额大于 0 时生成按钮可用，再次生成作为新请求，不复用上次结果；余额为 0 时按 AC-03 阻断。
- **证据**：离开前后截图、重新进入截图、刷新前后余额、结果数查询、请求日志和模型日志。
- **当前状态**：未执行。

## 3. 回归检查

额度改动不能破坏已有任务功能：

| 检查 | 预期 |
| --- | --- |
| 新增任务 | 任务立即出现在列表，余额不变 |
| 修改任务时长 | 时长保存成功，余额不变 |
| 标记任务完成 | 状态保存成功，余额不变 |
| 删除任务 | 任务消失，余额不变 |
| 已生成日程展示 | 任务分组和时长显示正常 |
| 失败后再次生成 | 使用当前任务列表，不沿用失败请求的旧结果 |
| 登录 / 退出 | 不影响账号任务和余额，重新登录后读取最新值 |

## 4. 通过标准与记录

- 所有 P0 案例通过；AC-10–AC-14 作为本版异常与可观察性门槛，也必须通过。
- 负余额数量为 0。
- 余额不足时模型调用增加量为 0。
- 模型失败、保存失败后余额与请求前一致。
- 超时或断网不出现自动重试，且页面不把未知结果说成“已扣”或“未扣”。
- 并发案例有可重复执行的证据，不只依赖主观判断。
- 未执行或失败的案例保留在记录中，并说明影响和后续处理。
