# 验收案例

规则、决策和文案编号（R、D、S）见[方案](01-solution.md)；任务编号（T）和接口约定见[任务拆解](03-tasks.md)。

## 怎么观察

| 观察什么 | 怎么看 |
|---|---|
| 模型调用次数 | 服务端日志里 `mock-ai.started` 的条数，一条代表一次计费调用；同一次调用的 `started` 与 `succeeded` 或 `failed` 共用同一个 `callId` |
| 冻结和退回 | T10 的结构化日志：每次冻结尝试、每次退回、每次结果未确认各一条，带用户、请求标识和时间 |
| 接口返回 | HTTP 状态和错误类型，取值见 03 的[接口约定](03-tasks.md#接口约定) |
| 余额 | 数据库 `User.credits`（`wasp db studio` 或 SQL）；页头"可用额度" |
| 日程数 | 数据库中该用户的 `PlanResult` 条数；页面上的历史日程 |
| 准备数据 | 用 `wasp db studio` 或 SQL 把测试账号余额设为指定值；描述含 `[fail]` 的任务会让模拟接口明确失败（见 [README](../../README.md)）；测试替身（T9）在测试里用假的结果替换保存或退回这一步，制造失败 |

除非另有说明，每条案例的前置条件都包含：1 条普通任务，时长为默认的 8 小时。

## 不变量

每条案例都要满足：

- I1：可用额度任何时候都不小于 0。生成路径由 T2 的条件更新保证；T8 的数据库约束防止其他代码路径写出负数。
- I2：所有请求结束后，初始余额减去最终余额，等于新增日程数。出现"结果未确认"（S10）时除外，以人工核对为准。
- I3：本页的请求结束后（S10 除外），页面会自动重新查询额度；查询成功、且期间没有其他页面或设备写入时，页头额度与数据库一致。

## 并发

AC-08 至 AC-10 由并发验证脚本执行（T7），要求见[并发验证要求](#并发验证要求)。AC-11 在页面上手动验证。

| ID | 场景 | 前置条件 | 操作 | 预期结果 |
|---|---|---|---|---|
| AC-08 | 余额只够 1 次 | 余额 1 | 同一账号同时发出 3 个生成请求 | `started` 恰好 1 条；1 个返回 200，2 个返回 402 / `NO_CREDITS`；这 2 个请求从发出到返回都在 250 毫秒以内（模拟调用要 500 毫秒），说明没有排队；余额 0；新增日程 1 |
| AC-09 | 余额够 3 次 | 余额 3 | 同一账号同时发出 5 个生成请求 | `started` 恰好 3 条；3 个返回 200，2 个返回 402 / `NO_CREDITS`，且这 2 个都在 250 毫秒以内返回；余额 0；新增日程 3 |
| AC-10 | 余额只够 1 次，模型失败 | 余额 1；唯一的任务描述含 `[fail]` | 同一账号同时发出 3 个生成请求 | 按 T10 的日志判断，冻结尝试以开始时间计：每条 `started` 之前都有一次成功的冻结；冻结成功的请求返回 502 / `MODEL_FAILED`，它的冻结以一次成功的退回结束；在某次冻结之后、它的退回之前开始尝试冻结的请求，都返回 402 / `NO_CREDITS`；最终余额 1；新增日程 0 |
| AC-11 | 快速连点 | 余额 3 | 在页面上快速连点两次"生成日程" | 只发出 1 个请求；`started` 1 条；余额 2 |

AC-10 不检查固定的调用次数。同时发出时，通常是 `started` 1 条、2 个 402；但某个请求如果在第一次退回之后才尝试冻结，它会合法地冻结成功，再调用一次模型（退回的额度可以再用，单次场景见 AC-06）。请求的发出和返回时间只反映客户端看到的顺序，所以先后以服务端日志为准。冻结尝试按开始时间计，是为了发现"让后到的请求排队等前一个结束"的错误实现：这类请求的开始时间落在冻结和退回之间，却没有返回 402。

## 并发验证要求

给 T7 的要求：

1. 每次运行前，把测试账号余额设为案例指定值，并记下该账号已有的日程条数。
2. 登录拿到会话，然后同时发出 N 个生成请求，不能一个接一个地发。记录每个请求的发出时间和返回时间。所有请求都要在第一个请求返回之前发出，否则这次运行标为"前置条件不满足"并重跑，不算失败。
3. 收集结果：每个请求的 HTTP 状态、错误类型和从发出到返回的时长；这段时间内 `mock-ai.started` 的条数；T10 的冻结和退回记录；最终余额；新增日程条数。
4. 运行期间不要有其他生成请求。`started` 日志里没有用户信息，只能按时间段统计；冻结和退回记录带用户和请求标识，可以用来交叉核对。
5. AC-10 按服务端日志的先后判断，冻结尝试以开始时间计，不检查固定的调用次数。
6. 逐项与上表比对，输出通过或不通过。每个案例连续运行至少 3 次，每次都通过才算通过。
