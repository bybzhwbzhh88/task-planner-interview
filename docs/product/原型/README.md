## 可点击入口的外观

所有可点击入口统一使用现有“从主线开始”按钮的深蓝底色 `#002142`、同色边框和白色文字 `#FFFFFF`，覆盖流程总览、各状态操作和底部演示导航。不可点击的说明卡片保留白底，禁用按钮保留灰色，以便阅读时辨认哪些地方可以点击。

这是本次用户提出的设计调整，不是招聘方规定的配色要求。按钮名称、跳转目标和业务规则不因填色改变。

## 主线：01—06

主线从“已有一份成功日程，还剩两次”开始。页面重点显示当前可用次数，并补充剩余次数和生成中占用。

| 画板 | 看什么 |
| --- | --- |
| 01 可以生成 | 剩余两次，尚无占用，可以开始生成 |
| 02 生成中仍可继续 | 第一份暂占一次，仍可提交另一份；编辑不改变已开始的请求 |
| 03 次数已被占用 | 两个请求分别占用一次，暂停新增，不自动排队 |
| 04 生成成功 | 第一份保存成功并使用一次；另一份继续处理，可用次数仍为零 |
| 05 生成失败可重试 | 第二份明确失败，不扣次并释放占用；保留成功日程，可以重试 |
| 06 次数已用完 | 重试成功后用完次数，仍可查看已保存日程 |

点击底部“演示：生成 1 成功”“演示：生成 2 失败”模拟后台完成。04 另有“演示：生成 2 成功”，进入 12 双成功分支。底部“原型演示”区只负责切换场景，不属于产品界面；原型不会真的等待模型完成。

Figma 与 HTML 都使用固定状态演示，待办和时长不能真实编辑；查询、读取和生成按钮展示预设的下一步，不执行后台处理。

## 分支：07—11

| 画板 | 看什么、下一步 |
| --- | --- |
| 07 结果待确认 | 超时不能直接判失败；查询本请求状态。本例查询后确认失败，进入 05 |
| 08 刷新后恢复 | 只读取最近成功结果、最新次数及处理进度；刷新不重复生成，也不解除真实占用 |
| 09 日程读取失败 | 本例次数已读取，仅日程读取失败；重新读取日程，不重新生成 |
| 10 尚无成功日程 | 新账号空态，由用户主动生成；本例省略处理中，直接展示首次成功后的 01 |
| 11 次数状态待确认 | 不显示旧额度或擅自当作零次；暂停新增，重新读取次数，保留已读到的成功日程 |

分支是不同情境，不按 07→11 连续发生。重新读取日程与重新读取次数是不同操作；读取失败、额度异常及后台处理失败也不能混为一谈。

## 新分支：12 双成功与 13—15 查看弹层

| 画板 | 用途 |
| --- | --- |
| 12 并发请求均成功 | 生成 1、生成 2 各成功一次，C / R / A 为 0 / 0 / 0；任务页默认展示后保存的生成 2，两条请求各有查看入口 |
| 13 查看生成1日程 | 6 小时、10:05 保存；从 04、05、07、08、09 或 12 的生成 1 成功行打开 |
| 14 查看生成2日程 | 4 小时、10:06 保存；从 12 的生成 2 成功行打开 |
| 15 查看生成3日程 | 4 小时、10:08 保存；从 06 的生成 3 成功行打开 |

弹层仅查看所选请求自己的已保存结果，标题、时长和保存时间对应同一请求。“关闭”和“返回任务页”均关闭弹层，HTML 还支持 Esc；查看和关闭不生成、不扣次，也不改变底页输入或请求状态。当前仍展示的成功请求提供查看入口，不新增完整历史管理。

预期实现中，查看期间如有另一请求成功，正在查看的弹层不自动切换；关闭回任务页后显示当时最新成功日程，而非强制恢复打开前的旧结果。刷新或重新进入恢复默认最近成功，不延续临时查看选择。指定结果读取失败时，应在保留请求身份的前提下重读同一请求，不重新生成、不用其他结果代替。本轮固定画板没有另绘读取失败弹层，也不模拟后台在查看期间完成请求，这些行为须在开发任务与验收中落实。

## 数据与设计边界

新账号初始三次来自 [题目要求](../../../TASK.md)。其余次数组合、生成序号、待办、时长和时间均为方案演示数据，不是原版实测或改进后测试。查看和读取已保存日程不消耗次数；其他并发请求可能在读取期间完成，账号状态仍以后台最新结果为准。
