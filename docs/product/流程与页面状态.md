## 怎么看

先看“00 生成流程”，再按“01 可以生成”至“06 次数已用完”阅读连续主线；“07”至“11”是独立分支，不表示它们依次发生。从 04 点击“演示：生成 2 成功”进入“12 并发请求均成功”，比较两个独立成功请求的查看入口。13—15 是从请求行打开的弹层，不属于主页面的连续流程。

各状态沿用同一任务页：次数区、待办与可用时长、生成操作、生成进度、最近一次成功日程。只改变必要的状态和反馈，不为每种结果新增页面。

原型使用固定状态切换，表单不能真实编辑，生成、查询和读取也不执行后台操作；“生成中”通过演示控件切换到预设结果，不会实时等待模型。

普通界面使用“当前可用次数”“生成中占用”“剩余次数”。下表的 C、R、A 仅用于设计核对：C 为尚未因成功消耗的次数，R 为正在处理请求占用的次数，A = C − R。页面数字来自同一份后台最新状态；未读取到时不显示为零。

## 主线与分支

**生成主线（预期业务行为）：**填写待办与可用时长 → 提交独立请求 → 后台检查并预留 → 生成进度 → 成功保存并扣次／明确失败释放占用 → 更新次数、请求反馈与最近成功日程。

- 只在当前可用次数大于零时接收新请求；资格检查与预留先于模型调用。仍有可用次数时，可以继续提交另一份日程。
- 次数已用完、已被占用或状态异常时，拒绝新增请求，不调用模型、不扣次、不排队。已经接收的请求继续执行。
- 成功时，保存结果、扣一次、解除该请求占用一起确认；可用次数不会因此增加。明确失败只释放自己的占用，不消耗次数。
- 网络超时等结果不确定时，查询该请求状态，再按实际成功或失败处理，不能直接引导重复生成。
- 刷新或重新进入页面时，读取最新次数、仍在处理的请求和最近成功日程，不重新生成、不解除真实占用。最近结果按服务端成功保存确认顺序确定。
- 成功请求仍在“生成进度”中展示时，提供“查看日程”，只读取该请求自己的成功结果。主页面默认展示最近成功日程；打开或关闭查看弹层不发起生成、不消耗次数，也不修改输入或请求状态。

主线的演示从已有一份成功日程、还剩两次开始：2/0/2 → 2/1/1 → 2/2/0 → 1/1/0 → 1/0/1 → 0/0/0。最后一步表示用户在失败释放占用后再次提交，并成功。

## 页面表达约定

- 可点击入口统一使用现有“从主线开始”按钮的深蓝底色 `#002142`、同色边框和白色文字 `#FFFFFF`，覆盖总览入口、各状态操作及底部演示导航；不可点击的说明卡片保留白底，禁用按钮保留灰色。这是本次用户提出的设计调整，不是招聘方规定，按钮名称、跳转目标和业务规则不变。
- 次数区突出“当前可用”，其余次数用于解释占用；占用不写成已经扣除。成功反馈与账号最新余额分别表达，不能因为本次未扣就声称账号总余额没变。
- “生成进度”用可辨识的生成序号对应各请求。一个请求被拒绝或失败，不覆盖其他请求的状态；后续独立请求不与已有请求合并。
- 日程区称“最近一次成功日程”，附可辨识信息和生成时间。失败时保留旧结果；并发成功按后台保存顺序更新，晚到的旧响应不能覆盖较新的结果。
- 已知没有可用次数时，生成按钮不可用，并常驻说明原因。后台仍负责拒绝旧页面或其他页面发来的超额请求，不能只依赖按钮。
- 刷新读取期间不把未知次数显示为零，也不重复提交。切换账号后清除上一账号的页面数据。
- 不新增充值、领取、每日恢复、自动排队或固定三个并发等承诺；不扩展完整历史管理。

## 按成功请求查看日程

本轮采用弹层查看，避免把“查看以前的成功请求”与主页面默认的“最近一次成功日程”混在一起：

- 成功行的按钮标为“查看日程”。04、05、07、08、09 可查看生成 1，06 可查看生成 3，12 可分别查看生成 1 和生成 2；失败或尚未确认成功的请求不显示成功结果入口。
- 弹层标题、时长、保存时间和安排均来自所选请求。仅执行读取；次数为零也能查看。不得将读取失败改成重新生成，也不得用另一份日程填入该请求弹层。
- 用户查看期间，如其他请求成功，弹层继续显示原来所选请求，不自动切换。后台更新的次数与最新成功身份仍应同步到任务页；关闭后回到该任务页，显示当时最新成功结果，不强制回到打开弹层前的旧结果。
- “关闭”和“返回任务页”执行同一种关闭操作；保留底页输入、账号和请求对应关系，不产生新请求、不扣次。HTML 演示同时支持 Esc 关闭。
- 刷新或重新进入任务页时，恢复默认的最近成功结果，不把临时查看某个请求当成新的默认结果，也不自动重新打开弹层。
- 指定请求结果读取中，应保留请求身份；读取失败时说明“这份日程暂时无法读取”，提供“重新读取”与关闭入口。重新读取仍针对同一个请求，不调用模型、不扣次。该异常属于交接和验收要求，本轮固定画板未另画读取失败弹层，也未声称执行过这一后台情境。

12 仅展示当前仍在列表中的两个成功请求，不新增完整历史列表、搜索或历史管理。静态演示不会在查看期间自动完成其他请求，因此本轮关闭回到底页不变的检查，不等于验证了后台更新期间关闭后展示最新结果。
