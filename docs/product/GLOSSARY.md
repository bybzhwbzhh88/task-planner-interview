# 名词说明

文中容易混淆的几个词，含义如下。具体规则见 PRD.md。

**待办任务**：用户录入的待处理事项，是日程生成的输入。
不要混用：生成请求、生成记录

**生成请求**：用户发起的一次生成日程操作。不同请求可以对应不同生成结果。
不要混用：待办任务

**日程结果**：基于一次请求提交的待办与可用时长生成的任务安排。
不要混用：待办列表

**生成成功**：日程已经生成且保存成功的结果。
不要混用：模型调用成功（尚不代表已保存）

**生成记录**：一次生成请求的状态与结果入口，用于区分并发请求、查询状态及找回结果。
不要混用：待办任务列表

**额度**：成功生成日程所消耗的次数单位。每成功生成一次消耗 1 次，新账号初始有 3 次。
不要混用：金额、Token、积分

**可用额度**：尚未消耗、也未被生成请求占用的次数，可供新请求使用。
不要混用：总剩余额度（未区分占用）

**占用额度**：为进行中请求暂时保留的次数，尚未确认为消耗。
不要混用：已扣额度

**账号并发上限**：同一账号同一时刻允许进行中的生成请求数量上限，本方案初值为 3。
不要混用：待办数量上限、每日次数上限

**明确失败**：能够确定本请求未成功完成生成与保存的结果。
不要混用：网络报错（可能只是页面未收到成功结果）

**结果待确认**：页面尚不能确定原请求实际处理结果的状态。
不要混用：生成失败、额度已退回

**提交时输入**：某次请求发起时的待办与时长，后续修改不改变这次输入。
不要混用：当前输入
