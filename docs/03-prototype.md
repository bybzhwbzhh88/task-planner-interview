# 03 · 界面与状态

只改「生成日程」这一块，不动任务列表的交互。目标：用户在任何时刻都能看到**还剩几次**、**这次扣没扣**。

## 1. 布局

额度标识放在生成按钮所在行的左侧，与按钮同高——用户准备点击时一定看得到。

```
┌──────────────────────────────────────────────┐
│  ☐ 写周报                              [删]  │
│  ☐ 准备面试                            [删]  │
│                                              │
│  今天可用的工作时长              [ 8 ]       │
│                                              │
│  剩余 3 次                        [ 生成日程 ]│
└──────────────────────────────────────────────┘
```

## 2. 四种状态

### 2.1 可生成

```
剩余 3 次                        [ 生成日程 ]
```

### 2.2 生成中

```
剩余 3 次                        [ ⟳ 生成中… ]
```

按钮禁用，防止重复提交。额度显示暂不变化，成功后刷新。

### 2.3 额度不足

```
剩余 0 次                        [ 生成日程 ]   ← 置灰

┌──────────────────────────────────────────────┐
│ 额度已用完                                    │
│ 本次未生成日程，也没有消耗额度。               │
│ 如需继续使用，请联系管理员补充额度。           │
└──────────────────────────────────────────────┘
```

按钮置灰只是**提前告知**；即使被绕过，服务端仍会拦截（R2）。

### 2.4 生成失败

```
剩余 3 次                        [ 重新生成 ]

┌──────────────────────────────────────────────┐
│ 生成失败                                      │
│ 模型没有返回结果，本次未消耗额度。             │
│ 可以调整任务后重试。                          │
└──────────────────────────────────────────────┘
```

## 3. 文案

文案的核心是回答三个问题：**发生了什么、扣没扣、接下来做什么**。

| 场景 | 标题 | 正文 | 主操作 |
|---|---|---|---|
| 额度不足 | 额度已用完 | 本次未生成日程，也没有消耗额度。如需继续使用，请联系管理员补充额度。 | 知道了 |
| 生成失败 | 生成失败 | 模型没有返回结果，本次未消耗额度。可以调整任务后重试。 | 重试 |
| 生成成功 | 生成完成 | 剩余 N 次 | — |
| 网络异常 | 网络异常 | 请求没有送达，本次未消耗额度。请检查网络后重试。 | 重试 |

## 4. 交互规则

| 规则 | 说明 |
|---|---|
| 余额刷新时机 | 生成成功、失败、额度不足后各刷新一次 |
| 按钮禁用条件 | 无未完成任务 / 生成中 / 余额为 0 |
| 重复点击 | 生成中禁用按钮，避免并发重复提交（服务端仍兜底） |
| 失败后保留输入 | 不清空任务与时长，用户可直接重试 |
| 成功后的编排 | 日程替换旧的展示，不追加，避免越滚越长 |

## 5. 与现有页面的差异

| 位置 | 现状 | 改后 |
|---|---|---|
| 生成按钮旁 | 无余额信息 | 常驻「剩余 N 次」 |
| 额度不足 | 弹窗「请检查账号状态」 | 说明原因 + 明确未扣额度 + 给出下一步 |
| 模型失败 | 通用错误弹窗 | 说明未扣额度 + 提供重试 |
| 余额为 0 | 按钮仍可点，请求后才报错 | 按钮置灰 + 提前说明 |
