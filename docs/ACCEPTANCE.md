# 验收与验证记录

当前交付为产品方案与交互原型。真实应用的额度缺陷尚未修复，以下业务验收用于开发完成后执行；原型验证只证明演示与方案一致。方案与任务映射见 [PRODUCT.md](PRODUCT.md)。

## 1. 真实应用验收准备

按 [README.md](../README.md) 安装并启动 Wasp 与数据库。每例使用独立测试账号，初始数据通过 `wasp db studio` 设置并记录。除特别说明，账号已登录、有一条普通任务、工作时长为 8 小时，没有进行中请求。每次记录账号、请求时间段、调用 `callId`、数据库前后值和页面反馈。

`额度 / 日程数` 指服务端 `User.credits` 最终值及该账号 `PlanResult` 总数；占用数量在实现新增的额度接口或存储中观察。模型启动次数按该测试时间段新增的 `mock-ai.started` 计算，同一 `callId` 只计一次。为了不混入其他请求，测试环境一次只跑一个账号案例；并发请求限于该例。

## 2. 验收案例

所有案例的实际后端结果目前均为 **未运行，待实现**。不得把预期数值粘贴成实际验证结果。

| 编号 / 目标 | 前置条件 | 操作 | 可观察的预期结果 |
| --- | --- | --- | --- |
| AC01 成功只扣一次 | 额度 3，日程数 N | 点击生成，等到完成 | `started` +1、`succeeded` +1；额度 2、日程 N+1、占用 0；可重新打开结果，显示“本次扣除 1 次” |
| AC02 零额度不调用 | 额度 0、占用 0 | 打开页面；再绕过按钮直接发送已认证请求 | 按钮不可用并解释原因；服务端拒绝；`started` +0，额度 0、日程不变；仍可编辑任务、查看历史 |
| AC03 两窗争最后一次 | 同账号两窗均显示额度 1 | 在模型返回前同时发送两次真实请求 | 仅一请求取得资格；另一返回额度占用提示且不排队；`started` +1；最终仅一成功，额度 0、日程 N+1、占用 0；失败窗口刷新后显示 0 |
| AC04 多请求不能超额 | 额度 3 | 屏障同时释放 5 个请求，确保都在首个模型返回前到达 | 恰好 3 次模型启动、3 次成功，另 2 次被拒绝；最终额度 0、日程 N+3、占用 0；过程中任何时刻额度和可用值不为负 |
| AC05 模型明确失败 | 额度 1；任务包含 `[fail]` | 生成；删掉失败任务后手动再生成 | 首次 `started` +1、`failed` +1；额度仍 1、日程 N、占用 0；明确提示未扣且输入保留。第二次可成功，额度 0、日程 N+1 |
| AC06 保存失败不形成半成品 | 额度 1；测试环境可注入保存错误 | 模型成功后令结果保存失败，再撤销注入重试 | 首次 `started` +1、`succeeded` +1，但额度仍 1、日程 N、占用 0；提示未保存且未扣；再次生成可成功。故障注入方法须在实现时补充 |
| AC07 旧余额不能放行 | 窗口 A/B 都曾读到 1；A 已成功，B 未刷新 | B 用旧状态直接发请求 | B 被服务端拒绝，新增 `started` 为 0；服务端仍为 0；B 获取最新额度，不依赖其旧用户快照 |
| AC08 一成一败分别结算 | 额度 2；两个独立请求分别取得普通任务和含 `[fail]` 的任务快照 | 两请求在重叠时间内执行；分别交换完成先后顺序 | `started` +2、`succeeded` +1、`failed` +1；两种顺序最终均为额度 1、日程 N+1、占用 0；失败只释放自己的占用 |
| AC09 不同账号互不占用 | A/B 各剩 1；各有任务 | 两账号同时生成 | 两者各有一次 `started` 和成功；两账号各剩 0、各增加一份日程；互相看不到任务/历史 |
| AC10 连点与历史 | 额度 3，已有可识别旧日程 | 本页快速双击；生成期间编辑任务；完成后查看历史 | 同页只提交一次；按钮生成中；本次使用开始时快照；旧结果不消失；历史倒序最多 5 份且只读；查看历史新增 `started` 为 0 |
| AC11 无效请求 / 未登录 | 未登录；或已登录但无任务/时长非有限数或不在 1–24 小时 | 直接向服务端发送请求 | 未登录拒绝；无任务或无效时长返回可理解的校验提示；均不占用、不扣除、不启动模型；正常任务编辑行为不变 |
| AC12 响应丢失不误导 | 额度 1，模型执行后只丢弃客户端响应，服务端继续执行 | 等待服务端完成，再恢复网络、刷新额度并查看历史 | 先显示“结果未确认”，不声称未扣，不自动重试；若服务端已保存则额度 0、日程 N+1；查看不调用模型；旧日程不能冒充本次确认 |
| AC13 额度读取失败 / 窗口恢复 | 已登录，额度请求被临时阻断 | 打开页面后恢复网络；再切出切回窗口 | 失败时显示无法查询及刷新入口；生成暂不可用；恢复后读取真实额度，不以默认 0/旧值放行；任务与旧结果保留 |

AC03–04 的“同时”需要真实 HTTP 请求或直接调用真实服务端入口，并通过同步屏障/延长测试模拟模型延迟确保重叠。逐个 `await`、只测内存函数或只点禁用按钮都不能证明数据库并发安全。执行后应保存脱敏的请求结果、模型日志、余额与日程数前后对照；不要记录密码、Cookie 或完整手机号。
