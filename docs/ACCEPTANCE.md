# 验收案例

以下是开发完成后的验收标准，**当前业务后端尚未按新方案实现、未执行这些集成验收**。原型演示另见 [VALIDATION.md](VALIDATION.md)，不得用原型通过替代下列后端结论。

## 测试准备与观察口径

按 [README](../README.md) 启动应用、数据库。使用独立测试账号 A/B，记下 ID；通过 `wasp db studio` 设置 User.credits。每个用例开始前记录初始额度 C、该账号结果数 P，并记录独立的日志时间窗；用例完成后刷新 Studio。只改测试账号，不清空别人的数据。

准备普通任务“整理面试资料”，可用时长 2 小时；失败用例新增任务 `[fail] 测试`。除并发用例外逐条执行；重置额度前确认没有请求进行中。结果数增量只统计当前账号。

一次 `mock-ai.started` = 一次模型调用。用 callId 关联 succeeded/failed；保存成功另以数据库结果和余额为证据。每个案例记录：版本、请求状态、started 增量、余额、结果数增量、页面状态；保留必要截图与日志，标出预期/实际，不含账号密码和私人任务内容。

## 核心规则

| 用例 / 规则 | 前置条件 | 操作 | 可观察的预期结果 |
| --- | --- | --- | --- |
| A01 / R1 | A 有 3 次额度，有普通任务；无请求进行中 | 点击生成，等待结束 | started/succeeded 各 +1；余额 3→2；PlanResult +1；显示本次日程和“已消耗 1 次，剩余 2 次”；顶栏同步为 2 |
| A02 / R2 | A 有 0 次额度；有普通任务 | 检查页面；再用真实请求绕过禁用按钮提交 | 按钮禁用；绕过前端的请求返回 402；started +0，余额 0，结果数 +0；可继续编辑任务、查看旧结果 |
| A03 / R3 | A 有 1 次额度，任务含 `[fail]` | 生成一次 | started/failed 各 +1；余额仍 1；结果数 +0；显示“未扣额度”及修正后重试提示 |
| A04 / R3、R4 | 紧接 A03，A 有 1 次额度 | 删除含 `[fail]` 的任务，再次生成 | started/succeeded 各 +1；余额 1→0；结果 +1；证明失败后锁已释放；显示额度用完 |
| A05 / R1 | A 有 1 次额度，有普通任务 | 成功生成后，再提交一次真实请求 | 第一次结果 +1、余额 0；第二次 402；两次合计 started +1；保留已生成结果，无充值或未实现入口 |
| A06 / R2 | 两个标签页登录 A；甲页仍显示旧额度 1；乙页先消费最后 1 次 | 甲页不先刷新，直接提交真实生成请求 | 服务端返回 402；甲页该请求 started +0；刷新甲页余额为 0；不根据旧额度放行 |
| A07 / R4 | A 有 1 次额度；第一请求已取得锁，mock 尚未结束 | 在第一请求完成前，同账号发起第二请求 | 第一请求成功；第二请求 409 且 started +0；合计 started +1、结果 +1、余额 0；第二请求不排队，页面提示等待并可刷新状态 |
| A08 / R4 | A 有 3 次额度；有普通任务 | 重叠发送两个请求；等首个结束后，再主动发送第三个 | 重叠请求只有一个进入 mock，另一个 409；第三个成功；总 started +2、结果 +2、余额 3→1；证明互斥不是“有额度便任意并发” |
| A09 / R4 | A、B 各有 1 次额度；均有普通任务 | 两账号同时生成 | 两者均成功，各 started +1、结果 +1、余额各为 0；没有互相返回账号忙碌；证据显示调用时间窗有重叠 |
| A10 / R6 | A 有 1 次额度；普通任务；开发提供测试专用故障注入，使 mock 成功后 PlanResult 保存失败 | 开启故障并生成；结束后关闭故障、再次生成 | 故障次 started/succeeded 各 +1，但余额仍 1、结果 +0；确认回滚后提示“保存失败，未扣额度”；恢复次成功，锁无泄漏 |
| A11 / R1、R4 | A 只有 1 次额度；脚本可控制请求重叠 | 同步释放 10 个生成请求；等待全部结束 | 最多 1 次成功、started 最多 +1、结果最多 +1，余额不低于 0；重叠到锁的请求 409，首请求完成后才到达者 402；不要求所有拒绝都是同一状态码 |

## 体验与边界

| 用例 | 前置条件 | 操作 | 可观察的预期结果 |
| --- | --- | --- | --- |
| A12 / R5、R7 | A 有 2 次额度，已有一份历史结果 | 生成中断开页面网络；服务端可继续处理，随后恢复网络并同步状态 | 不宣称“未扣额度”；不自动再生成；旧结果标为上次；同步请求只读取，started +0；看到权威余额、当前生成状态与带时间的结果后再决定是否重试 |
| A13 / R5 | 甲乙两页同账号；甲页在后台，乙页成功消费一次 | 回到甲页；再点击“刷新状态” | 焦点触发及手动同步均能读到最新余额和自己的结果；同步不扣费、不调用模型 |
| A14 | 未登录，或没有任务，或可用时长不在 1–24 小时 | 分别提交 | 未登录 401；无任务/非法时长按约定 400；started +0、余额/结果不变；页面提示登录、添加任务或修正时长；接口也有校验 |
| A15 | 可读取余额接口暂时失败；另一次加载已明确返回 0 | 分别查看页面 | 读取失败显示“暂时无法读取”与刷新入口，不能伪装为 0；真实 0 显示额度已用完；两者按钮均不可生成 |
| A16 | A 有历史结果，新增一条失败任务 | 生成失败，再编辑任务 | 旧结果保留且标为上次；任务不被清空；提示可修正后重试；不将旧结果误标为本次成功 |

## 并发复现与判定

开发需要补充可重复执行的真实接口脚本，并在验证记录中给出命令。产品不猜测尚未确认的 Wasp 请求路径、鉴权字段或故障注入实现。

脚本要求：为隔离账号预置余额与普通任务；复用同一账号有效会话；通过屏障同时释放请求；输出各请求状态、开始/结束时间、最终余额和结果数增量；关联服务端 started 记录。A07/A08 必须能证明第二请求到达时首请求尚未结束（例如测试专用延迟与开始屏障），不能仅凭“两个标签页先后点击”断言重叠。

A11 反复执行至少 5 轮，每轮恢复初始余额与日志计数；一轮只有一个成功但产生多个 started 也判失败。请求到达时间跨越首请求完成时，402/409 可混合，只要无额外调用与透支。脚本或环境未准备好时，记录“未执行”，不填通过。
