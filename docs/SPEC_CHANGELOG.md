# SPEC 调整记录

交付环境没有 Git，无法用提交历史展示“初稿 → 实现”的差异；这里保留影响行为的调整。定稿见 [SPEC.md](../SPEC.md)。

## v1 初稿（实现前）

- 预占用 `updateMany`（带 `credits > 0`），随后单独 `findUnique` 读余额。
- 模型明确失败与普通异常都走 500。
- 页面用 toast 提示额度不足，按钮在额度 0 时仍可点击。
- 验收 AC-02 只写“点击生成”。

## 定稿调整（实现后）

| 调整 | 原因 | 影响 |
| --- | --- | --- |
| 预占的 `updateMany` + `findUnique` 放入同一 `$transaction` | 若扣减成功但余额读取失败，旧写法会丢 1 个额度且没有退款入口 | 读取失败时扣减回滚；`SPEC.md` §4 |
| 模型明确失败映射为 502，并保留 `MOCK_AI_REJECTED` 错误码 | 页面需要区分“模型拒绝（未扣费）”和普通系统失败 | `operations.ts`；AC-03 |
| 余额 0 时按钮直接禁用并说明下一步 | 避免用户点击后才看到错误；服务端 402 仍保留给并发/绕过页面的请求 | AC-02 拆成页面与服务端两个观察点 |
| 页面改为持久的结果条，不再只用 toast | 用户需要停留可读的“是否扣费、还剩多少、下一步” | `DemoAppPage.tsx` |
| 增加保存失败退款、退款失败单测 | “失败净消耗 0”需要覆盖结果落库失败；退款失败不能静默 | AC-05；`tests/generate-plan.test.ts` |
| 测试命令加 `--test-isolation=none` | 当前 Windows 沙箱禁止测试 runner 再 spawn 子进程 | `npm run test:quota` 可直接复现 |

- 不修改 Prisma schema 和迁移；余额字段已存在。
