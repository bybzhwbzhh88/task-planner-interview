# 实际验证记录

数据库原子预占使额度成为模型调用的前置条件；成功保存才形成消费，明确失败恢复额度。当前实现通过 Wasp 编译、两份 TypeScript 检查、12 项集成测试及主要页面验收。**1 个额度 / 10 个并发请求：1 成功、9 次 402、1 次模型调用、余额 0、1 条日程。**

## 环境与复现

- 时间：2026-10-23，北京时间 11:37 起；容器日志使用 UTC（相差 8 小时）。
- Windows Docker Desktop 的隔离 Linux 容器；Node v24.22.1、Wasp 0.25.0、Prisma 5.19.1、PostgreSQL 17.11、Vitest 4.1.11。
- 项目复制到容器 `/work` 的 Linux 文件系统，数据库 `planner_test`；未使用模拟数据库。schema 无改动，仅应用仓库已有迁移。
- 命令：`TEST_DATABASE_URL=... bash scripts/verify.sh`，具体可复制配置见 [RUNBOOK](RUNBOOK.md)。容器内实际执行 `bash scripts/verify.sh`，退出码 0。
- [完整命令日志](evidence/verify.log) 保留 case 摘要、mock 的 callId、异常注入堆栈、编译/迁移结果与最终 12 passed；仅移除 ANSI 控制字符。
- 12:00 复跑（同一容器、同一条命令、未改代码）：退出码 0，仍为 12 passed，耗时 6.8 秒。用于确认脚本可重复执行，而非只成功过一次。

## 自动验收

预期与前置条件见 [SPEC 验收表](../SPEC.md#验收案例)，表中实际结果来自日志，每个用例均独立建号并清理。

| 案例 / 操作 | 预期 | 实际 |
| --- | --- | --- |
| A1：新账号普通生成 | 默认 3 额度，成功后 2 / 1 条结果 / 1 次调用 | 一致；保存内容与返回日程一致 |
| A2：0 额度，登录上下文故意给旧余额 999 | 402 / 0 额度 / 0 结果 / 0 调用 | 一致 |
| A3：`[fail]` 失败后改普通任务重试 | 失败后余额 1、无结果；重试成功后余额 0、1 条结果 | 一致；累计 2 次调用 |
| A4：1 额度，`Promise.allSettled` 并发 10 次 | 1 成功、9 次 402、0 额度、1 结果、1 调用 | 一致 |
| A5：3 额度，并发 10 次 | 3 成功、7 次 402、0 额度、3 结果、3 调用 | 一致 |
| A6：1 额度，并发失败后重试 | 全部拒绝、余额恢复 1；重试可成功 | 实际失败批次仅调用 1 次，恢复余额 1；重试后 0 额度 / 1 结果 |
| A7：两个账号各 1 额度 | 各成功一次，各 0 额度 / 1 结果，不能互读 | 一致；合计 2 次调用 |
| A8：未登录、0/-1/25/NaN/Infinity 时长、无任务 | 401/400；0 调用、余额和记录不变 | 一致；余额/历史查询也拒绝未登录 |
| A9：注入明确 P2003 保存拒绝 | 500、归还为 1、0 结果、1 调用 | 一致 |
| A10：注入归还失败 | 503、记录 refund_failed，不虚称退款 | 一致；余额 0、无结果，保留核查状态 |
| A11：保存结果不明 | 503、记录 save_uncertain，不自动归还 | 一致；1 次调用、余额 0 |
| A11-committed：写入后抛响应丢失 | 返回 503，但日程存在且仍消耗 1 | 一致；余额 0、结果 1、调用 1 |

A9–A11 是异常注入，不声称真实断网；其余运行原有 `generateMockSchedule` 的 500ms 延迟。测试直接调用实际 `generatePlan` 和查询实现，未替换 Wasp 的 `HttpError`。

## 浏览器验收

本地地址 `http://localhost:3300`（容器映射到 3000，API 映射 3301→3001），使用独立验收账号。容器专用 `host` 与 API URL 设置未提交到产品源码。

| 案例 | 实际操作与观察 |
| --- | --- |
| U1 | 注册后余额 3；添加普通任务并生成，按钮显示生成中并禁用；结束后顶部及页面均为 2，出现成功提示、日程和历史。刷新后余额 2，展开历史能看到原日程。[截图](evidence/ui-success.png) |
| U2 | 添加 `[fail]` 任务后生成，收到“额度已归还 / 删除失败任务后重试”；余额仍 2，历史未新增。删除失败任务再生成成功，余额变 1。[失败截图](evidence/ui-failure.png) |
| U3 | 两标签页同账号、均显示 1 额度，同时点击生成。一页成功、另一页提示暂无可用额度；两页最终显示 0，生成按钮禁用，原有历史保留。[被拒绝标签页](evidence/ui-concurrent-rejected.png) |

未单独验证“无本页操作、只重新获得窗口焦点”的自动刷新行为；目前依赖 Wasp/React Query 默认机制，显式刷新按钮和每次生成结束后的刷新已实际验证。未运行移动端与自动化浏览器回归。
