# 验收案例

所有余额与模型调用断言均以服务端/数据库记录为准。模型调用数指模拟模型入口实际被调用次数。

| ID | 场景与前置条件 | 操作 | 预期结果 |
| --- | --- | --- | --- |
| A1 | 余额 1，有效任务 | 发起生成并等待完成 | 日程成功保存；余额为 0；模型调用 1 次；成功后净扣 1 |
| A2 | 余额 0，有效任务 | 从页面发起生成 | 按钮不可用并说明原因；无模型调用；余额仍为 0 |
| A3 | 余额 0，有效任务 | 绕过页面直接请求服务端 | 服务端拒绝；无模型调用；余额不变 |
| A4 | 余额 1，任务描述包含 `[fail]` | 发起生成 | 显示失败且本次未扣额度；无日程保存；余额恢复为 1 |
| A5 | 余额 1，有效任务 | 两个会话同时请求 | 最多 1 个请求预留并进入模型；余额不为负；另一个明确收到额度不足 |
| A6 | 余额 3，有效任务 | 并发发起 5 个请求 | 最多 3 个获得额度并进入模型；其余不调用模型；余额不为负 |
| A7 | 余额 2，有效任务 | 处理中连续点击生成按钮 | 页面只提交 1 次请求；按钮在处理中禁用；余额最多净减 1 |
| A8 | 余额 2，已有一条日程 | 成功生成后刷新页面 | 新余额仍与服务端一致；已保存日程仍可见，不重复扣额 |
| A9 | 余额 1，模拟结果保存失败 | 触发保存失败 | 不向用户报告成功；按定义释放预留；无成功日程；异常可在服务端核对 |
| A10 | 余额充足，但没有有效待办 | 点击生成或直接请求 | 页面阻止无效提交，服务端也拒绝；无模型调用、无额度变化 |
| A11 | 余额 1，模型明确失败 | 失败后修改任务并重试 | 首次失败净扣 0；修改后可重试；若重试成功则净扣 1 |
| A12 | 余额预留后模拟服务中断/退款异常 | 检查用户反馈和服务端记录 | 不伪装成普通模型失败或声称退款成功；系统异常可追踪；符合本轮已披露限制 |

## 并发结果解释

并发请求获得额度不等于最终成功：若已预留请求中的模型明确失败，该请求应释放预留，净消耗为 0。A5/A6 的普通成功任务用于验证额度上限；失败释放由 A4/A11 单独验证，避免把“预留数”和“最终扣额数”混为一谈。
